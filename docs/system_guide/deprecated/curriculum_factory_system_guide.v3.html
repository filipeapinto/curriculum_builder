curriculum_factory

A single-operator, contract-first pipeline that turns one curriculum manifest into reviewed, accepted curriculum units and a workbook. It is a LangGraph state machine in which all routing authority is code-owned: models author and review artifacts, and are structurally prevented from deciding what happens next.

1Purpose and boundary

The system consumes one immutable curriculum manifest and one immutable engine tree, and produces accepted curriculum units — domain data, written content, visuals, a rendered PDF — and finally an assembled workbook, entirely underneath a caller-supplied output root. Its single actor is a human operator on their own machine, holding their own Claude and Codex subscription credentials. There is no service, no API and no second user. observed

Its entry interface is one CLI invocation; its exit interface is a JSON terminal record on stdout plus a process exit code. Between those two points it makes exactly one call to compiled.invoke() (run_curriculum.py:827) — the CLI runs no product step itself.

What it is on the hook for

  • Deriving the unit count and order from the supplied manifest, not from configuration.
  • Proving, before any model runs, that the sandbox and both model CLIs are actually present and behave as the frozen registry expects (D03_PROVE_CAPABILITIES).
  • Never letting a model decide a route, a verdict or a terminal.
  • Writing nothing outside the output root it was given.
Exclusions a reader will otherwise assume
  • Curriculum content is not in the package. curricula/, policy/, schemas/ and meta_prompt/ are repository-owned data supplied by path at runtime. Packaging confirms this: pyproject.toml includes only curriculum_factory* from src/.
  • No scheduling, queueing, concurrency or multi-run coordination. One flock per output root is the entire concurrency model; a second process gets exit 3 and does nothing.
  • No graceful stop. The mechanism exists but is not wired — see §12.
  • No backup, retention, rotation or cleanup of anything it writes. Verified absent across the checkpoint DB, all ledgers and the artifact store.
  • Not portable off macOS. build_sandboxed_argv raises CapabilityProofFailed when sandbox_mechanism() is "none", which is the case on any non-Darwin host (transport.py:928).

Assumptions it makes about its environment, each enforced rather than documented: an operator-owned ~/.claude.json and ~/.codex/auth.json exist; no *_API_KEY variable is set (their presence fails the capability proof); pandoc/typst and the poppler tools are installed; and the output root is empty or absent for a fresh run.

2Architecture

The package installs one engine generation: the Plan 26 LangGraph runtime.

GenerationModulesReached byStatusEvidence
Plan 26 — current langgraph_factory/ (21 modules), driven by run_curriculum.py curriculum-factory-run-curriculum The one production graph. All routing, state and evidence discipline described in this guide is here. observed
Single-engine package The retired Plan 25 controller, bridge, evidence finalizer, Gemini helpers, and supporting modules are not installed. Importing curriculum_factory has no legacy-engine side effects, and the sole published console script is curriculum-factory-run-curriculum. observed

Within Plan 26 the composition is deliberately one-directional. graph.py owns registration and the common node boundary but no node body; node bodies live in nodes/, model_nodes.py, workbook.py, repair.py and acceptance.py — and PRODUCTION_BINDING_MODULES (graph.py:101) rejects a callable from anywhere else by stable ID, so "the graph compiled" cannot mean "the graph compiled against a stand-in". Routing (routing.py) is a pure function of state that reads no service, no clock and no filesystem. The transport (transport.py, 2 847 lines) is the only module that may start an external process.

3Graph behavior

The graph is framework-defined, not prompt-orchestrated. Nodes and edges are registered into a LangGraph StateGraph at build time and a model never chooses the next step: a node body emits a pending_guard record carrying one declared string value, and a pure guard function maps that value to exactly one destination. A value outside the frozen table raises RoutingViolation rather than resolving to a terminal, because a table/body disagreement is a build defect, not a run outcome (routing.py:1-26). observed

Compiling the graph on this machine yields 50 nodes and 158 edges, digest 0e1eca87080aa102…. Two rules run before any node-specific routing rule, in this order: a classified pending_failure routes to the terminal writer (to D91 for a model node, whose failures are the one class a classifier may retry), and only then does an observed interrupt route to the interrupt gate. Failure deliberately outranks interruption so that an episode which broke and was asked to stop is not recorded as merely INTERRUPTED.

The unreachable frontier

Verified gap: five registered nodes cannot be entered

Compiling the production graph and walking it from __start__ leaves five nodes with no incoming edge and no path from the entry point:

M06_REPAIR_NAMED_UNIT_ARTIFACT · M07_REVIEW_ACTUAL_WORKBOOK · M08_REPAIR_NAMED_WORKBOOK_DEFECT · D28_REDUCE_WORKBOOK_EVIDENCE · D32_RECOMPUTE_FINAL_RELEASE

Cause, traced. Every model node is reached only through D90_RESERVE_MODEL_ATTEMPT, whose conditional path map is the tuple at unit_graph.py:117-125. That tuple lists M01–M05 and stops. Its own comment states the rule it then breaks: "the path map has to enumerate every model job this path can reserve for, or the compiled edge cannot reach the one reserved." M06, M07 and M08 are absent. D28 is reachable only from M07, and D32 only from D28, so both fall with them.

Consequence for an operator inferred: a run that reaches D19 with a model-repair plan, or reaches D27, has no compiled edge to take. COMPLETE is written only by D32 (workbook.py:1172), so a full --all run cannot reach its success terminal. This is inference, not observation: no run in this inspection got that far.

Conflicting evidence. graph.py:721-731 states that D24–D32 "are both real, wired members of the one compiled production graph" and that the deferred D05 → D24 row "resolves automatically". The first half is observably true — D05 → D24 and D24 → D25 → D26 → D27 all compile. The claim does not hold for the model jobs behind them. workbook.py:1280 does register conditional edges out of D28, D32, M07 and M08; they are simply edges out of nodes nothing can enter.

4Node and tool contracts

Node bodies come in two shapes. Deterministic nodes (D…) take (state, RuntimeContext) and may touch the artifact store, the retriever and the clock, but never a model. Model nodes (M…) receive a narrowed context and reach a model only through the transport. Both are wrapped by a common boundary (graph.py:366) that injects the context, converts any unhandled exception into a classified pending_failure plus a fully-formed SYSTEM_FAILURE terminal candidate, and re-raises LangGraph's own control-flow exceptions untouched.

The terminal contract, concretely

UNIT_ACCEPTED (0) and COMPLETE (0) are the only kinds that claim success, and each is re-proved from scratch: COMPLETE requires a PASS release audit whose key matches, a current workbook head equal to the claimed hash, and exact manifest coverage — no extra unit, no missing unit. PAUSED_PREREQUISITE (11) is rejected unless pending_failure["class"] == "pause", so a schema or tool fault cannot wear a pause candidate to look benign. INTERRUPTED (10) and PAUSED_PREREQUISITE are the only resumable kinds.

5State and data

FactoryState is a 77-field TypedDict in which every field declares exactly one reducer through typing.Annotated; a field with zero or two reducers raises StateInventoryError at import (state.py:224). The reducer, not the writing node, is what makes concurrent and replayed writes safe — so the merge rule is the contract a maintainer must read before adding a field.

What survives a crash

Four independent layers persist, and they do not all agree on how carefully:

  • The checkpoint DB — .langgraph/checkpoints.sqlite3, LangGraph's SqliteSaver with WAL + synchronous=FULL + busy_timeout=30000, re-verified after setup() because setup may relax them. Thread id is <run_id>:episode:<ordinal:06d>; checkpoint_ns is always the empty string. observed
  • Hash-chained JSONL ledgers under .langgraph/ — each record carries prev_hash and a contiguous ordinal, so a deleted or reordered line is detectable rather than merely lost.
  • The content-addressed artifact store — blobs by SHA-256, version records, and one mutable file per stream: the head pointer. That head pointer is the only thing in the entire store that is ever overwritten; anything under an accepted/ path is refused even with overwrite=True and is chmod'd 0444/0555.
  • Egress receipts — .evidence/egress_receipts.jsonl, the only evidence log with a production writer.
Two durability guarantees that are declared but not wired

flush_checkpoint_durability() (persistence.py:555) commits, forces a full WAL checkpoint and fsyncs the DB, the WAL and the directory. Its own docstring says this is required "before a receipt or terminal may pass". It has no caller in src/. Likewise AdmissionLedger.admit() — the mechanism documented as making "a crash between a committed side effect and its checkpoint non-duplicating on retry" — is never called, so admissions.jsonl is only ever created empty.

What that costs the reader: a machine that loses power between a node returning and SQLite flushing its WAL may lose the last checkpoint, and the artifact-store side effect that node already committed will be redone on replay. The idempotency keys make redoing it safe; the missing flush means you may replay further back than the guide's own design intends. inferred

7Models and prompts

Eight model jobs are frozen in langgraph_factory/config/model_jobs.v1.yaml (frozen: true, job_count: 8, enforced by the loader at transport.py:190). Prompts and output schemas are resolved as package resources by bare name, never relative to the working directory, and their file digests are folded into the graph digest — so the same topology over a changed prompt is not the same graph.

Every job carries timeout_seconds: 900 and retry_limit: 1. No token budget, cost cap or context limit is declared anywhere, and there is no fallback chain — the opposite is enforced. assert_identity_matches raises IdentityMismatch if the model the CLI reports executing differs from the registry, if the family differs, or if a review ran in the authoring family; that class is system-terminal and never retried. A maintainer looking for "what happens if Sonnet is unavailable" should read this as: the run stops.

Structured output and its failure path

Models are invoked as subprocesses, not APIs. Codex writes result.json into its workspace; Claude's structured output is extracted from the last result event of its stream-json output. Parsing is strict single-document, and each way it can fail is its own class — empty_result, fenced_result (any markdown fence), malformed_json, trailing_material, result_is_not_an_object, duplicate_json_key, non_finite_json_constant, then schema_invalid_result against the job's JSON Schema (Draft 2020-12).

Two gates then run that a reader would not expect from a schema check. assert_no_authoritative_fields rejects a candidate — or a schema — containing any control-plane key such as a route, verdict or terminal name (transport.py:274). And workspace.assert_no_undeclared_writes(permitted_new=("result.json",)) fails the attempt if the model wrote any other file. Together these are the mechanism behind "a model has no routing authority": it is enforced at the transport boundary, not trusted to the prompt.

Model-selection manifests (declared, prompt-read)

policy/routing/ holds four YAML manifests — model_registry.v1.yaml (capabilities and availability), task_taxonomy.v2.yaml (task classes and risk profiles), routing_policy.v1.yaml (candidate-pool and escalation policy) and quality_gates.v1.yaml (observable acceptance gates) — plus a folder-index readme.md. Per that readme, none of the four is an input to code: the rules that bind a run live in the meta prompt's ## Routing section, which reads these files as its data. inputs.py:67 cites model_registry.v1.yaml only in a comment pinning the two driver CLIs. This entire manifest set is therefore declared, not observed — no traced run was found that shows a model consuming them, and this guide does not know whether the fixed eight-job table above and this candidate-pool mechanism are two names for the same routing path or two coexisting ones. That ambiguity is unresolved in v2; a maintainer changing routing behavior should locate the meta prompt's ## Routing section first and confirm which mechanism is live before trusting either description in isolation.

8Deployment

There is no deployment

The pattern deploy/** matched nothing in the source register — recorded as an evidence gap rather than silently dropped. There is no Dockerfile, no infrastructure-as-code, no service manifest, no hosting configuration anywhere in the repository. This section is therefore about the only environment that exists: an operator's laptop. observed

Runtime topology is a single Python 3.13 process (pinned >=3.13,<3.14) that spawns one short-lived sandboxed child per model activation, per render and per inspection. There are no workers, no queues, no network services, and no horizontal scaling story: concurrency is bounded to one process per output root by flock, and to one in-flight model activation by the graph's own shape.

The platform is not portable. sandbox-exec is macOS-only, and the transport fails closed when it is absent. This has a consequence for the one automated environment that does exist:

Nothing degrades gracefully if they are down — the attempt bound is reached and the run terminates CONVERGENCE_EXHAUSTED. inferred

10Security and privacy

There is no authentication and no authorization of a caller, because there is no caller: whoever can run the CLI already has the operator's shell. What the system does instead is constrain what its own child processes may do — and that machinery is unusually thorough, which makes its gaps worth stating precisely.

ControlWhat is actually enforcedEvidence
Process isolation Every model, render and inspection child runs under /usr/bin/sandbox-exec -f <profile>. Absence of the mechanism fails the run rather than degrading to an unsandboxed spawn. observed
Egress from the factory process EgressGuard patches socket.connect, connect_ex and create_connection process-wide and denies by default. Every denial is receipted with a reason and a traceback origin. observed
Model APIs are unreachable from Python api.anthropic.com, api.openai.com and chatgpt.com are denied even with an active grant — the parent process may never talk to a model API. observed
Source retrieval https only, exact-match host allowlist (no suffix matching), port pinned, every resolved address required to be globally routable, redirects re-validated both before and after, 25 MB cap, content type allowlist. DNS rebinding is a named, receipted denial reason. declared
Credentials No API key is ever read or set. Claude gets four non-secret fields copied out of ~/.claude.json into a disposable home plus a read-only Keychain symlink; Codex gets a read-only symlink to ~/.codex/auth.json. Verified gaps
  • The sandbox constrains the model child by port, not by host. Its network rule allows outbound TCP to any host on 443 and 80 and UDP on 53. The code says so itself and records it as a non-required capability facet named subprocess_network_scope (transport.py:1058-1066). A compromised or misbehaving CLI child can reach any host on those ports; the elaborate parent-side allowlist does not apply to it.
  • M01's WebSearch is outside every control described above. It executes inside the Claude child, so neither EgressGuard nor RetrievalPolicy sees it. Only the locators it returns are re-checked. Granting it also forces that activation to --permission-mode bypassPermissions.
  • Model stdout and stderr are persisted verbatim and hashed. Redaction is a single rule — argv tokens longer than 200 characters are replaced by a hash — applied to one field. Nothing scrubs a credential or personal datum that a CLI happened to print to stderr, and nothing redacts prompts, model outputs or state values in any ledger or checkpoint.
  • No retention or deletion exists anywhere. Everything the system writes — checkpoints, ledgers, receipts, artifacts, model output — accumulates indefinitely under the output root. By construction it cannot be truncated: a hash chain with contiguous ordinals fails its own audit if a line is removed.
  • No incident owner is recorded. No CODEOWNERS, no escalation contact, no security contact anywhere in the repository. unknown

11Observability

The design intent is unusually strong: six hash-chained evidence logs (events, activations, routes, executions, checkpoints, index), each append-only, flock-protected, fsync'd, schema-validated, and able to distinguish a tampered record from a deleted one from a torn append.

Blind spots — read this before you rely on anything above
  • EvidenceStore.append() is never called from src/. The store is constructed at graph.py:227 and injected into every node's RuntimeContext as evidence_service, and no node body uses it. Five of the six logs have no writer anywhere; the sixth has one writer called only from tests. evidence/*.jsonl is never created at runtime. observed
  • Consequently evidence_index_entries is always empty, so D98's log_high_water_mark ceiling is checked against nothing, and write_audit_report() never runs.
  • No logging framework at all. grep for import logging, prometheus, opentelemetry, statsd, datadog, sentry across src/ returns zero matches. No levels, no handlers, no diagnostic log file. Console output is 15 print() sites.
  • No metrics, traces, spans, dashboards, alerts, health endpoint or SLO. Nothing is exported anywhere.
  • No timing anywhere. No node duration, no model-call latency. Timestamps exist only as time.time_ns() inside ledger payloads.
  • The legacy ExecutionLogger — the one thing in the repo shaped like an operational log — carries no run id, no episode id and no time of day, only a date. It is also unreachable from langgraph_factory.
  • Episode leases are opened and never closed. close_episode() has no caller in src/, so every run leaves an open lease and every --resume is forced down the orphan-recovery branch. The plain resume branch appears to be unreachable in practice. inferred

What an operator actually has. Two things: the terminal JSON printed on stdout (kind, exit code, resumability, heads, validation results) and .evidence/egress_receipts.jsonl, which records every allowed and denied network attempt with its reason. Everything else — whether a node is slow, which unit is in flight, how many attempts have been spent — must be inferred by reading the SQLite checkpoint or watching the process. Plan for that before an incident, not during one.

12Operations and recovery

A healthy run looks like Exit code 0 with a terminal of kind UNIT_ACCEPTED (for --unit) or COMPLETE (for --all), an accepted_unit_receipts entry per unit, a non-empty .evidence/egress_receipts.jsonl with no unexpected denials, and an output root containing .langgraph/checkpoints.sqlite3 plus the artifact tree.

Prerequisites

  • macOS with /usr/bin/sandbox-exec; Python 3.13.x; claude, codex, pandoc/typst and poppler tools on PATH.
  • Logged-in Claude and Codex CLIs. No *_API_KEY variable set — their presence aborts the run.
  • The package importable. Note that a bare python3 -m pytest -q from the repository root fails collection with ModuleNotFoundError unless the package is installed (pip install -e '.[dev]') — there is no pythonpath setting in pyproject.toml. observed

Procedures

# 1 · Check readiness. Read-only, creates no run, takes no --authorization.
curriculum-factory-run-curriculum \
  --engine-root PATH --curriculum PATH --output-root PATH --preflight
# exit 0 = ready · exit 3 = not ready (missing capability, or output root collision)

# 2 · One unit. Output root must be absent or an empty directory.
curriculum-factory-run-curriculum \
  --engine-root PATH --curriculum PATH --output-root PATH \
  --unit L01 --authorization auth.json

# 3 · Whole manifest.
curriculum-factory-run-curriculum ... --all --authorization auth.json

# 4 · Resume an interrupted or paused run, into the SAME output root.
curriculum-factory-run-curriculum ... --resume --authorization auth.json

Do not
  • Do not send SIGINT expecting a clean stop. InterruptToken.install() has no caller in src/, no code calls set(), and is_set() returns a private in-memory boolean — the .langgraph/interrupt.token file is written, never read. There is no signal handler in run_curriculum.py at all. Ctrl-C therefore kills the process at whatever point it had reached, leaving an open episode lease and no terminal record. D96 is compiled and reachable in the topology but nothing can trigger it. observed
  • Do not delete or empty the output root to clear a COLLISION. It holds the only copy of the checkpoint, the identity envelope and the accepted artifacts. Move it aside instead.
  • Do not edit anything under the output root by hand. The identity envelope is 0444 and hash-verified; ledgers are hash-chained; artifact records are re-hashed on read. A hand edit surfaces later as CheckpointCorrupt or EvidenceCorrupt, and the run refuses.
  • Do not change --engine-root, --curriculum or --output-root between a run and its resume. All three are hashed into run_id; the resume refuses with an identity drift naming the field.
  • Do not run curriculum-factory-finalize-evidence and trust its output. It always returns 0, and two of its six validations invoke CLI flags that no longer exist.
  • Do not run two processes against one output root. The second gets exit 3 — which is the system working — but do not defeat it by copying the root.

Triage

  1. Read the terminal JSON on stdout first. It carries the kind, the failing node, the safe artifact heads and the validation rejections. It is more informative than anything on disk.
  2. If the kind is SYSTEM_FAILURE with node: "D98_WRITE_TERMINAL" and cause: "integrity", another node proposed a terminal that D98's independent re-derivation rejected; the rejected_candidate_kind and the rejection list name what did not hold. Escalate — this is a correctness fault, not an environment fault.
  3. Check .evidence/egress_receipts.jsonl for denials. A host_not_pinned or unauthorized_socket_no_active_retrieval entry usually means the retrieval profile does not list a host the run needed.
  4. For a crash with no terminal (killed process, power loss), the run left an open lease. Resume takes the orphan-recovery path, which re-enters through D92 at a validated frontier with the transport and retriever disabled for that step.
Recovery has no backup and no rollback There is no restore procedure, because there is no backup: nothing copies the output root, and the only rollback primitive in the system is git, which does not cover generated output. Artifact history is preserved by construction (every version is retained; only the head pointer moves), so a bad head can in principle be reasoned about from the version records — but no code exists to move a head backwards. Treat the output root as the single copy of the run and back it up yourself before intervening. observed
