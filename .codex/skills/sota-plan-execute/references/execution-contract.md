# SOTA research execution contract

Execution requires:

- one explicitly approved, self-contained plan version as the sole project execution contract;
- immutable prior plan versions;
- stable run, activity, source, finding, and artifact identifiers;
- paired start and terminal records for material activities;
- source provenance and claim-to-evidence links;
- measured budgets and declared behavior when a measure is unavailable;
- recorded retries with failure cause and changed approach;
- deviations recorded before application;
- independent challenge with dispositions;
- deterministic verification of required artifacts and claims where possible;
- explicit human acceptance or rejection.

Do not rely on separate project budget, protocol, allocation, or control files. If an execution-critical instruction is absent from the plan, return to planning for vN+1.

Execution must stop or return to planning when a required authority decision or material plan change is encountered. A completed tool call, model response, file, or report is not sufficient evidence of acceptance.
