Can Codex Invoke Claude for an Independent QA Gate?

Executed plan v1 · run RUN-CAL-20260819-01 · 19 August 2026

Decision: defer operational adoption

Codex can invoke Claude through a bounded local subprocess and obtain fail-closed, schema- and digest-bound receipts. That establishes technical feasibility, not operational reliability or high-consequence independence. Current use should be limited to non-authoritative research advice; an operational pilot is deferred pending representative independently labeled artifacts, semantic controller validation, uncertainty estimates, separate execution identity, and remote append-only receipts.

Findings

FND-001 — Supported route (high feasibility evidence, limited operational applicability). Current Claude Code documentation supports non-interactive, structured execution; local Claude Code 2.1.233 successfully invoked claude-sonnet-5 in safe mode with application/server tools disabled and no session persistence. One failed receipt exposed internal tool_use and auxiliary Haiku model usage during structured-output retries, so single-model/no-tool operation is not established. Sources: Claude programmatic mode, CLI reference.

FND-002 — Controller assurance (high mechanical evidence, incomplete semantic assurance). The controller enforced artifact digest, JSON Schema, model/session/usage receipt, 15-minute timeout, $0.25 per-call ceiling, and fail-closed errors. Unsupported schema annotations and structured-output exhaustion were caught as QA_ERROR. Schema-valid PASS receipts could still contain nonempty findings, and reviewer-authored digest objections could still false-block; future integrity and state/finding consistency must be controller-owned.

FND-003 — Diversity is not accuracy (moderate evidence, limited generalizability). On 42 live/provider receipts per condition, Claude achieved 73.8% exact state accuracy, below Sol and Terra at 85.7%. All returned FAIL on 18 clear-defect receipts; PASS-case outcomes were Claude 13 PASS/4 FAIL/1 ERROR, Sol 17/1/0, and Terra 16/2/0. These are corpus-specific observations, not general model rankings. Original research documents judge bias and does not justify vendor diversity as correctness proof: MT-Bench, PoLL, self-preference bias.

FND-004 — Failure semantics dominate (high benchmark evidence, high applicability). Every condition recalled clear defects; most errors came from overblocking valid artifacts or treating ambiguous criteria as FAIL rather than QA_ERROR. Criteria quality and controller semantics matter more than vendor label.

FND-005 — Independence is multidimensional (high conceptual evidence). The Claude route is separate in process, frozen context, model family, and vendor, but not in host integrity. A process sharing the same user and filesystem cannot provide adversarially strong evidence. Digest/provenance controls help auditability but do not solve shared-host forgery. See SLSA provenance.

FND-006 — Direct API/SDK is the production candidate (moderate evidence, untested here). The API/Agent SDK exposes cleaner programmatic control, but requires dedicated credential governance and a separate pilot. The local CLI is sufficient for a repository pilot, not yet a production service.

Recommended next stage

REC-001. Defer operational use. Claude may be used only for non-authoritative research advice; its verdict must not block release or satisfy acceptance.

REC-002. Harden the controller so integrity fields are controller-owned and PASS ⇒ findings=[]; document internal structured-output tool/model behavior.

REC-003. Build a representative, independently labeled corpus; add confidence intervals and compare deterministic tests, static analysis, rubric repair, human adjudication, diverse panels, and direct API/SDK operation.

REC-004. Require separate execution identity and remote append-only receipts before high-consequence testing. Revalidate CLI/model/schema, pricing, auth, and rate limits before any further live phase.

Limitations and unknowns

No production/customer artifacts were used. Human labels were authored before calls but were not dual-adjudicated. The corpus has templated triplicates and limited modalities. Client-reported Claude cost is estimated. Codex subscription calls lack per-call dollar billing. Host integrity is weak. API/SDK and MCP routes were not empirically benchmarked. External sources were not archived. These limits require deferral of operational adoption.
