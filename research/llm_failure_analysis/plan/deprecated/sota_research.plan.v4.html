SOTA Research Plan: Documenting LLM-Execution Failure

Research current mature practices for recording, reconstructing, explaining, and learning from failed or wasteful LLM execution, then determine what this repository should adopt.

1. Research question

Primary research questionWhich mature mechanisms should this repository adopt or adapt to make failed, wasteful, or falsely successful LLM executions observable, explainable, reproducible, and useful for governing the next execution?

The reported incident—approximately 20% of weekly usage consumed overnight while producing graph-system documentation and revising a generic documentation skill—is the motivating case. The percentage, sequence, causes, and outcomes remain claims until supported by repository or usage evidence.

2. Research method

The work combines a systematic literature review of external evidence with a forensic reconstruction of the repository incident. PRISMA 2020 governs reporting of identification, screening, exclusion, and inclusion. Software-engineering SLR guidance governs the review protocol, search strategy, quality assessment, extraction, and synthesis.

EXTERNAL EVIDENCE

Systematic literature review

Identify and appraise standards, primary research, official technical documentation, mature open-source implementations, and documented industry practice.

INTERNAL EVIDENCE

Incident reconstruction

Reconstruct what ran, why it ran, what it consumed, what it produced, what controls operated, and which evidence is missing.

COMPARATIVE SYNTHESIS

Repository applicability

Compare external mechanisms against demonstrated failure modes, current controls, implementation cost, and residual risk.

4. Research execution graph

This is a directed, attributed state graph. It uses LangGraph’s execution concepts: START, nodes, fixed edges, conditional edges, parallel fan-out/fan-in, shared state, checkpoints, interrupts for human decisions, and END. Graphviz DOT is the canonical diagram source because it directly represents directed nodes, edges, attributes, and clusters; the SVG below is its document rendering.

Canonical DOT representation

The published graph must be generated from versioned DOT rather than hand-maintained SVG. Node attributes carry executor type, model, evidence inputs, outputs, and checkpoint policy. A later executable LangGraph implementation must be checked against the same node and edge manifest.

digraph sota_research {
  rankdir=TB;
  START -> inventory_evidence -> map_evidence_landscape;
  map_evidence_landscape -> select_review_design -> write_protocol;
  write_protocol -> approve_protocol;
  approve_protocol -> write_protocol [label="revise"];
  approve_protocol -> {review_external_evidence reconstruct_incident} [label="approved"];
  {review_external_evidence reconstruct_incident} -> appraise_and_compare;
  appraise_and_compare -> challenge_findings;
  challenge_findings -> appraise_and_compare [label="revise"];
  challenge_findings -> synthesize_report [label="pass"];
  synthesize_report -> verify_artifacts;
  verify_artifacts -> synthesize_report [label="fail"];
  verify_artifacts -> accept_research [label="pass"];
  accept_research -> END;
}

6. Evidence selection and appraisal

Evidence classes

  1. Standards and primary specifications
  2. Peer-reviewed and original research
  3. Official technical documentation
  4. Mature open-source implementations and tests
  5. Documented industry incidents and engineering practice

Protocol requirements

  • Exact sources, queries, dates, and retrieval records
  • Explicit inclusion and exclusion criteria
  • Duplicate removal with receipts
  • Quality criteria for each evidence class
  • Claim-to-source mapping
  • Contradictions and missing evidence retained
  • PRISMA selection counts

The preliminary study determines whether observability records, causal analysis, cost controls, evaluation, durable execution, and governance form one synthesis or focused subreviews. It does not assume that logs and traces are separate domains.

9. Budget and stopping rules

The preliminary study receives a small human-approved ceiling. Its measured yield and cost estimate the full review.

Measure

Candidate yield, duplicate rate, screening time, extraction size, repository volume, model usage, and unresolved concepts.

Authorize

Hard limits for model calls, tokens, elapsed time, sources, concurrency, retries, and spend where available.

Stop or interrupt

Stop at protocol completion, saturation, repeated failure, limit threshold, inadequate evidence, or required human authority.

A retry requires a recorded failure and a changed input, hypothesis, executor, or method. Completed nodes resume from their checkpoint.
