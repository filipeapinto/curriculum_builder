Sources and template design basis

Direct investigation sources belong here. The reusable report contract is additionally informed by the following primary guidance.

  • NASA Software Change Request / Problem Report guidance
  • NASA non-conformance levels and fields
  • NASA SWE-082: Authorizing Changes
  • NIST SP 800-218, Secure Software Development Framework
  • NIST SP 800-86, evidence collection and integrity guidance
  • OMG Structured Assurance Case Metamodel 2.3
  • Google SRE: Effective Troubleshooting and Postmortem Culture
  • NIST AI RMF 1.0 and NIST AI 600-1 GenAI Profile
  • W3C PROV-O
  • GitHub issue-form syntax
  • WHATWG HTML data blocks, RFC 3339, and WCAG 2.2

Hard authority boundaries

This report may

  • Preserve the original suspicion and evidence.
  • Confirm, partially confirm, refute, or leave the claim inconclusive.
  • Record human disagreement and create a later immutable version.
  • Become eligible for planning after human acceptance.

This report may not

  • Edit or remediate the affected system.
  • Approve a root cause, fix, budget, deployment, or release.
  • Open its own plan gate or accept itself.
  • Erase the original report, negative evidence, or human pushback.
