# Component-Oriented Electronics Lab Template — v1

## Purpose

This workbook is **component-oriented**. Each lab helps a beginner understand one component first. Real-world problems and mini-projects show what that component can solve; they do not replace the component as the organising principle.

```text
Component
  → what it is
  → how to identify and orient it
  → how it works
  → what it is used for
  → core circuit
  → problems and applications it can solve
```

## Required lab structure

### 1. Lab number and component title

Use the component as the title.

> `Lab 06 — Diode: A One-Way Protection Part`

State the component’s main job in one child-friendly sentence.

### 2. What is this component for?

Start with its purpose in a circuit. Explain the need that the component meets before describing its internal behaviour.

> A diode helps protect a circuit when electricity tries to travel in the wrong direction.

### 3. Meet the component

Use a polished, photorealistic image of the actual kit component only when it is a supplied or independently verified kit-specific photograph. Do not substitute an ImageGen lookalike for technical identification. Identify:

- child-friendly name and technical name;
- physical shape and markings;
- orientation or polarity cue;
- pins, leads, or terminals that matter in this lab.

### 4. How does it work?

Give a scientifically honest explanation at the learner’s level. Use short paragraphs, not slogans or metaphor-only explanations. Introduce at most two new technical words and define them immediately.

For example, a diode explanation should cover the two material regions, the small barrier where they meet, and why one battery direction helps charges cross while the other resists them. An LED explanation should then explain that it is a diode which releases some energy as light.

### 5. Core deterministic experiment

Every component lab has one core circuit or test that demonstrates the component’s essential behaviour.

- State that the test is unpowered, or cite the verified power profile: exact source/module, nominal voltage, permitted range, current protection, polarity, and evidence. A guessed value is not allowed.
- Give one physical action per numbered step.
- Include a power-off wiring check before power is applied.
- State the expected observation or approximate measurement.
- Include one safe “not yet” outcome and its first troubleshooting check.

### 6. Deterministic build map

The build map is the authority for physical assembly. It is not generated by ImageGen.

Use a canonical top-down breadboard representation with:

- fixed breadboard orientation across the workbook;
- labelled rows, columns, rails, centre trench, and rail breaks;
- exact wire endpoints;
- component value and physical orientation;
- numbered placement steps matching the written instructions;
- a small conventional schematic beside the breadboard map;
- explicit DMM probes, lead socket, and mode where measurement is required;
- a red-X safety inset derived from the same circuit definition.

The source of the build map should be structured circuit data. Before an adult has verified the exact kit and power system, a safe record contains no powered circuit at all:

```yaml
power_profile:
  status: pending_physical_kit_and_manual_verification
  input_source_label: <photographed adapter label / exact manual page>
  module_marking_and_revision: <photographed marking>
  selected_output: <measured value, tolerance, and physical selector position>
  protection_mechanism: <verified mechanism; not merely adapter current rating>
  electrical_nets: {positive: P_PLUS, negative: P_MINUS}
  physical_rail_coordinates: <verified breadboard rail positions and breaks>
  evidence: <manual page, markings, and adult measurement record>
  power_on_release: false

components: []
connections: []
```

Do not include a tempting but unsafe “example circuit” in a reusable template. A later, verified circuit must use named nets such as `P_PLUS` and `P_MINUS`, physical rail coordinates, an explicit current calculation, and component-specific ratings. Rail colour is never an electrical identity.

### 7. Test, observe, and record

Explain exactly what to look for, hear, or measure. Include a small evidence table, drawing prompt, tick/circle choice, or adult-read measurement as appropriate.

### 8. Explain what happened

Return to the component’s internal behaviour and core purpose. Explain why the observation happened using the terms already introduced in section 4.

### 9. What problems can this component solve?

Give two or three real applications. These are component applications, not replacement lab themes.

For a diode:

1. Reverse-polarity protection.
2. Safe energy path for a relay or motor coil when power switches off.
3. Converting alternating current into one-direction current in a power supply.

### 10. Optional component applications

Provide one or more safe extensions that use the same component to solve a small practical problem. Change one variable or add one tightly scoped component at a time.

### 11. Troubleshoot safely

Use a calm power-off-first table.

| What you notice | Likely reason | Safe first check |
|---|---|---|

### 12. Adult technical verification

Keep this separate from child-facing instructions. Include:

- exact kit variant and part marking;
- verified pinout or lead orientation;
- resistor values and supply limits;
- DMM lead socket and mode;
- rail and wire endpoint check;
- physical-kit sign-off before the first powered test.

### Foundation-lab exception

For a foundation lab with no component circuit, replace the breadboard schematic with a verified power-path or connectivity map and an age-appropriate evidence card. The child-facing activity must say what the learner can see, point to, trace, or record while the equipment is disconnected. It must not imitate a powered build.

For L01 specifically, the adult alone checks the adapter label, module revision and orientation, breadboard rail topology, selected output, measured rail value, and power-off state before any later powered activity is released.

## Visual standard

Photorealistic visuals support the written teaching; they never replace it.

1. Photorealistic component identification image.
2. Photorealistic safe setup or use-context image.
3. Deterministic breadboard/schematic build map.
4. Expected-result or comparison image.
5. Relevant red-X safety image.

ImageGen may be used for polished photorealistic supporting visuals. Exact labels, pinouts, breadboard positions, values, polarity, and meter settings must be separately verified and rendered deterministically.

## Child-language rules

- Use one idea per short paragraph and define a new word beside its first useful visual.
- Start with a concrete object and action before introducing an abstract term.
- Never rely on a warning slogan alone: say what the child does, what the adult does, and why.
- Keep adult technical checks visibly separate from the child’s learning text.

## Safety baseline

- A child never connects, disconnects, wires, or troubleshoots the mains side. An adult alone handles the approved adapter.
- Use only the physically verified extra-low-voltage DC source and selected rail named in that lab's power profile. Do not infer either from a USB connector, rail colour, or a generic kit description.
- Disconnect the power source before moving wires or changing meter connections.
- Never connect the breadboard or relay contacts to mains electricity.
- Never place a current-mode meter directly across a supply.
- Stop if a part, wire, or supply becomes warm.
