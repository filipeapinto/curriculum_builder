How the meta prompt works

It builds the generator. The generator builds the labs. The meta prompt never writes curriculum itself — it produces templates_v7/ and proves it with exactly one finished lab, L01.

Contract: meta_prompt/meta_curriculum_builder.prompt.v6.md plus the six section files it names.

1 · What the contract is

The prompt is short on purpose: mission, boundary, the asset table, the order of work, the report. Rules that need room to be exact live beside it and bind exactly as it does. A companion is different — it is an input a worker reads, ranked below every section.

2 · How a run proceeds

Sixteen steps, and the order is the point. The contract is verified before it is obeyed; the only write that precedes the logger is the directory the logger needs; after that every action is logged before it is taken.

3 · The six gates

In order, and each one proves something the previous cannot. Gate 0 passes before any other artifact exists, because the previous build logged an entire run through a logger nobody had tested.

4 · Why the split cannot quietly shrink the contract

Splitting one file into seven creates a new way to fail: move a rule somewhere nothing reads and every check still reports a pass. Four independent claims about the contract's shape must agree, and the last of them lives outside the contract entirely.

What the checks do not say. They prove the contract is whole in shape: every file present, every heading where it is claimed to be, nothing unowned. They do not read the prose beneath a heading, and they do not read meaning — a contract whose paths all resolve and whose instructions contradict each other would pass. Past that point the record is git history and review.
