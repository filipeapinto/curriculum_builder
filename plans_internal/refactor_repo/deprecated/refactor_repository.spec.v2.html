Repository refactor prompt

This prompt replaces the narrower product-name rebrand workflow. It audits and refactors repository identities and layout conventions as one coordinated change.

Refactor scope

The workflow audits and refactors all repository identities and layout conventions together:

  • product/display name;
  • Git repository slug and local checkout directory;
  • Python source layout under src/;
  • generated, cached, historical, and deprecated directories; and
  • other names that do not match their contents or common conventions.

Recommended identity map

The product, repository, Python distribution, and import package are related identities, but they serve different syntactic contexts. The refactor must not apply one spelling indiscriminately everywhere.

Python source-layout conclusion

Use src/curriculum_factory/, not Python files directly under src/.src/ identifies installable source; curriculum_factory provides the import namespace; its children represent the system’s internal responsibilities.

The current runtime/ package already mixes orchestration, model routing, retrieval, rendering, persistence, validation, and command-line execution. The recommended eventual organization is:

src/
└── curriculum_factory/
    ├── __init__.py
    ├── cli.py
    ├── orchestration/
    ├── routing/
    ├── retrieval/
    ├── rendering/
    ├── validation/
    └── persistence/

The first migration should prioritize behavioral equivalence: move the production package, establish pyproject.toml and installed-package testing, update imports and entry points, and correct every __file__-based repository-root calculation. Responsibility-based splitting can then occur without mixing structural movement with behavioral redesign.

Keep policy/, schemas/, curricula/, and outputs/ outside src/. They are repository data, contracts, domain inputs, or generated artifacts—not Python source. Add another top-level package below src/ only if a genuinely independent reusable or deployable component emerges.

Output policy

Keep the boundary; clean up its contents.outputs/ remains the ignored runtime destination. It should be empty between runs and must not be the permanent home of tests, fixtures, audits, or cited evidence.

This conclusion is supported by the current implementation: runtime/io.py constrains every accepted output root beneath ENGINE/outputs/; the controller, session bridge, and curriculum graph enforce that rule; tests create temporary runs there; the meta-prompt and policy document outputs/<run>/; and .gitignore excludes generated children.

Conclusions

  1. The task is a coordinated repository refactor, not a product-name replacement.
  2. src/curriculum_factory/ is the appropriate Python foundation. The package can contain several responsibility-based subsystems without creating separate top-level packages.
  3. The broad runtime name should not remain the permanent architecture. Preserve behavior during the initial move, then split by responsibility.
  4. outputs/ is still necessary as the runtime write boundary; most existing children are not appropriate permanent residents.
  5. Durable fixture and research evidence must move out of ignored local state before obsolete output runs are removed.
  6. Remote-repository and parent-directory renames occur last and require explicit authorization. In-repository validation must not depend on those external operations.
