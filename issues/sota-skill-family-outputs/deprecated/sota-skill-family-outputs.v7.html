The SOTA verifier cannot detect requirements omitted by a plan

The verifier is explicitly told to derive its checklist only from the approved plan. There is no separate family checklist against which the plan itself is tested. A plan can therefore omit a family control, and verification will omit that same control.

DecisionReported issueVerificationRoot causeCorrectionOpen itemsApproval

Decision

CONFIRMED: sota-verify/SKILL.md says, “Derive the checklist only from the approved plan.” No other SOTA-family instruction requires the verifier to test the plan against a non-waivable family baseline.

Consequence: if a plan omits a required control—such as a provenance field, lifecycle record, challenge disposition, or terminal state—the verifier has no independent rule requiring it to report that omission.

Recommended correction: define a short family baseline and require verification to run it before plan-specific checks.

Decision requested: approve, reject, or request changes to the three corrections in this report. Approval authorizes planning only.

Severity

P0: this is a false-assurance path. A plan and its verification can agree with each other while both omit a family requirement.

Confidence

High. The controlling instructions state the behavior directly; no inference from file-format differences is needed.

Root Cause

Defect: verification has no authority source above the individual plan.

Cause: the workflow treats the plan as both the object being trusted and the sole source of rules used to verify the resulting run. No independent family contract constrains what the plan must contain.

AffectedAll plans created by sota-plan-create, runs executed by sota-plan-execute, and reports checked by sota-verify.
Not affectedStudy-specific questions, search strategies, evidence sources, experiments, sample sizes, analyses, and conclusions.
