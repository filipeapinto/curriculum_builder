Two SOTA runs used incompatible contracts, and both contain independently verified defects

The audit found specific differences in run location, record schemas, lifecycle evidence, verification outcomes, and terminal states. Some differences are legitimate study variation. Ten classes are contract or implementation inconsistencies. Historical skill invocation remains unproved.

DecisionReported issueEvidenceDiagnosisProposalUnknownsApproval

Decision

CONFIRMED, WITH THE ORIGINAL CLAIM NARROWED: the current family contains shared high-level controls, so it is false that there is no common method at all. What is missing is a sufficiently precise and enforced contract for canonical locations, record shapes, lifecycle and terminal states, and cross-run verification semantics.

What the audit proved: ten inconsistency classes were traced to current instructions, plan clauses, run records, or missing rules. It also proved direct plan-conformance defects inside both audited runs.

What the audit did not prove: it did not prove which exact historical skill versions or agent assignments produced either run.

Decision requested: accept the findings register and decide which proposed canonical contract should govern redesign. This report does not authorize implementation.

Severity

P0 / SEV-2_CRITICAL: inconsistent conformance and terminal semantics can create false assurance about whether research was complete, verified, or accepted.

Final audit disposition

PARTIALLY_READY: the inconsistency evidence is sufficient for redesign planning; provenance and several schema-policy decisions remain open.

Rejected explanationMarkdown/CSV versus JSON does not by itself prove inconsistency. Any format can be valid when its schema, authority, and producer/consumer contract are explicit.

Root Cause

Defect: the family’s shared controls are expressed primarily as prose obligations whose concrete artifact locations, record shapes, precedence, and terminal semantics are supplied by each plan.

Cause: responsibility is split without a decisive family layer: plans define the executable details; role skills return semantic summaries; execution follows the plan; verification derives its checklist from the plan. No single current contract binds all four layers to one interoperable record model.

AffectedFamily-level comparability and conformance of SOTA plans, runs, role handoffs, verification, resumption, and final state reporting.
Not affectedLegitimate research-method choices and study-specific evidence.
ImpactEquivalent concepts can be recorded differently; equivalent defects need not receive demonstrably equivalent verification outcomes; readers cannot reliably compare completion, verification, acceptance, and research support across runs.
ConfidenceHigh for current-contract and run-record findings; unknown for historical attribution to exact invoked skill versions.
