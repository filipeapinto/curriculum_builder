Root Cause

Defect: equivalent lifecycle and evidence concepts are not bound to one interoperable family record contract, so cross-run conformance and terminal meaning are not deterministic.

Cause: family controls are divided among plan prose, execution instructions, role outputs, and plan-derived verification without one authoritative contract binding their paths, fields, states, precedence, and tests. Confidence is high for current instructions and run records; historical invocation attribution is unknown.

Recommended correction

The original prompt required a canonical-contract proposal rooted at execution/<run-id>/. The owner later selected the compact topology below in issue v4. That selection is a human design decision, not an audit finding.

research/<sota-slug>/
├── plan/
│   └── <sota-slug>.plan.vN.html
└── runs/
    └── <run-id>/
        ├── report.html
        ├── execution-log.json
        └── evidence/          # optional
ChangeImplement the owner-selected compact topology; define which prospective facts belong in the plan, which actual events belong in the execution log, and which findings and terminal states belong in the report. Add a minimal conditional SOTA plan template, family precedence rules, normalized state envelope, and non-waivable verifier checks.
Targetsota-plan-create, sota-plan-execute, role output contracts, sota-verify, family guide, schemas, and deterministic tests.
Why this corrects the issueIt gives equivalent concepts one authoritative representation and test while preserving legitimate study extensions.
Acceptance testsGenerate minimal and complex plans; execute both into the compact topology; validate both with the same baseline; prove a plan cannot weaken baseline requirements; evaluate both legacy runs read-only; verify separate research, execution, verification, acceptance, and authority states.
