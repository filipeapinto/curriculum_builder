Repository routing policy is bypassed by SOTA-local model and budget rules

Executive summary

VERIFIED. The repository already defines a central model registry, task taxonomy, routing policy, routing-decision schema, and routing checks, but sota-plan-create separately owns a skill-local model-allocation policy and requires generated plans to embed that allocation and independently define measurement-unavailable behavior. The central and SOTA policies can conflict: central high-risk routing permits only gpt-5.6-sol at minimum xhigh, while the SOTA policy assigns preliminary research to gpt-5.6-terra at high and assigns challenge to gpt-5.5, which is not in the central registry. There is no central routing-level budget/fallback manifest equivalent to the proposed budget-policy.yaml. The reported external token-measurement stop is plausible and consistent with a local generated plan found here, but that specific other-repository run is an attributed claim because its artifacts are not available in this repository.

Root-cause analysis

Root cause: routing authority is not exclusive. The repository routing subsystem governs curriculum task classes, while the SOTA family evolved a second self-contained allocation contract and directs each generated plan to become the controlling execution contract. No repository-wide ownership rule prevents skills or plans from redefining model eligibility, effort, fallback, or telemetry-unavailable behavior.
