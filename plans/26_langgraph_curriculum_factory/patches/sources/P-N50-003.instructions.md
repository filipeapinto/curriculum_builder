The controller only admits a node when its result report contains a bare,
machine-parseable status line matching this exact pattern (multiline regex):

  ^status:\s*(PASSED|NOT_AVAILABLE|BLOCKED)\s*$

That means a line, on its own, starting at column 0 with lowercase `status:`
followed by one of PASSED, NOT_AVAILABLE, or BLOCKED and nothing else — no
markdown bold (`**...**`), no capitalized `Status:`, no extra words on that
line. See `plans/26_langgraph_curriculum_factory/results/N40_CLI_CUTOVER.result.v1.md`
line 3 for a correct example: a line reading exactly `status: PASSED`.

`plans/26_langgraph_curriculum_factory/results/N50_ADVERSARIAL_REGRESSION.result.v1.md`
currently has `Status: **PASSED**` near the top instead, which does not match
the required pattern, so the controller cannot detect the reported status and
blocks the node even though the work itself is complete and correct.

If that file already exists with the wrong status line, use the Edit or Write
tool to replace only that one line with a bare `status: PASSED` line (or
`status: BLOCKED` / `status: NOT_AVAILABLE` if that is the true outcome).
Change nothing else in the file — do not rewrite content, evidence, hashes, or
any other section. Then verify with Read that the line now matches the
pattern exactly before finishing.
