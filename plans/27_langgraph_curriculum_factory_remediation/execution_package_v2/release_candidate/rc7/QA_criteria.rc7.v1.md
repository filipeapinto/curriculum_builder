## Why this session exists

`release_candidate/rc6` (session `019ffd79-1dc8-7b02-a665-73a510859535`) reached `FAIL`
with two findings, recorded in full in `release_candidate/rc6/QA/rounds/round-01.response.json`:

- **RC6-QA-001 (blocker):** every one of rc6's ten embedded fenced sections carried one
  extra blank line immediately before its closing fence, so an extracted section's own
  SHA-256 never matched the manifested/live file's SHA-256 — the bundle could not
  actually serve as a byte-identical frozen review target.
- **RC6-QA-002 (major):** `tests/test_execution_package_v2.py` exercised the real
  `scan_node.py --node N20_PROVIDER_TRANSPORT --graph implementation.graph.v6.yaml`
  command (the exact command that reached a genuine `BLOCKED` with 16 violations under
  graph v5, finding `N20V2-F01`) but never asserted `code == 0`, `payload['valid']`, or
  an empty violations list — only that it scanned the right file scope. The required
  automated regression proof that N20's real write set now passes cleanly was absent.

This rc7 snapshot fixes both findings and changes **nothing else**. rc6's own
underlying engineering content — the `N20V2-F01` graph-level fix itself — was never in
question and is carried forward byte-identical:
`implementation.graph.v6.yaml`, `controller/scan_node.py`, `tools/validate_plan_v2.py`,
`tools/validate_result_v2.py`, all three `prompts/*.v6.md` files,
`schemas/spec_approval.schema.v3.json`, and `contracts/spec_approval.v3.yaml` are
byte-identical to rc6's own copies (confirm by SHA-256 against `manifest.v1.json`
below). `tests/test_execution_package_v2.py` is the only file this session changes:
it strengthens `test_n20_node_mode_includes_its_newly_owned_egress_module_and_test`
with the missing assertions and adds one new dedicated test,
`test_n20_real_node_scoped_scan_is_the_regression_proof_that_n20v2_f01_is_fixed`. The
bundle itself (`rc7_review_bundle.v1.md`) is regenerated by a small deterministic
script that writes each fenced section as the opening fence, the file's exact bytes,
and the closing fence on the very next line — no inserted or removed line — and
re-verifies every section's extracted SHA-256 against the live file's SHA-256 before
writing the bundle to disk.

`release_candidate/rc1` through `rc6` in full (including each one's `QA/` session),
`implementation.graph.v4.yaml`, `implementation.graph.v5.yaml` (preserved at
`deprecated/`), `spec_approval.schema.v1.json`/`v2.json`, `spec_approval.v1.yaml`/`v2.yaml`,
