# Run 27 QA criteria v1

## Immediate rejection

- Starting implementation without a hash-bound corrected-spec approval gate.
- Treating Plan 26 v1, current code, or installed CLI presence as provider
  authorization.
- Retaining or adding a production Gemini/Google route, credential, model,
  transmission permission, prerequisite, or fallback.
- Using a billed API key, direct model HTTP API, custom endpoint, or hidden
  provider fallback.
- Assigning generation/repair and final judgment to the same provider family.
- Returning `ready: true` when a mandatory subscription driver cannot perform a
  permitted content-free authentication/operation probe.
- Parsing human Markdown as the node admission protocol.
- Admitting a node whose graph entry has no machine-runnable verification or no
  exact result-schema validation command.
- Giving two nodes overlapping write ownership, even when their execution is
  sequential, without redesignating one exclusive owner.
- Changing the node-result schema after N00 admission or assigning that frozen
  protocol file to any execution node.
- Retaining a descendant receipt after an ancestor input/output digest changes.
- Accepting nondeterministic evidence at a stable path or restoring stale bytes
  to satisfy a receipt.
- Proving graph nodes only through isolated function tests rather than the
  production compile point.
- Allowing shared call sites or integration tests to have no deterministic owner.
- Claiming activation from unit tests, configuration, compilation, preflight,
  simulation, or a one-unit-only proof.
- Allowing N90 to omit its terminal recommendation, allowing another node to
  provide one, or allowing N90 to recommend `BLOCKED_SPEC_NOT_APPROVED`.
- Enforcing the production-code scan against historical plans or outputs instead
  of its declared denominator, or granting active tests any exception from their
  separate zero-occurrence retirement scan.
- Carrying an obsolete provider-specific test into N60's full-suite denominator,
  or leaving a migration-affected predecessor test without an exclusive owner.
- Letting N80 write to, resume, copy, or admit bytes from N70's output root;
  N70 evidence may be consulted only as read-only corroboration.

## Required implementation proof

1. Corrected v2 authority and explicit user approval bind one digest.
2. Plan 26 v1 and historical evidence remain unchanged.
3. All eight jobs match the approved Claude-generation/Codex-judgment profile.
4. Production imports and subprocess routes contain no forbidden provider/API
   path and fail closed without fallback.
5. Preflight distinguishes executable identity, authentication mode, observable
   entitlement, permitted operation, and data boundary.
6. The exact Run 26 false-ready condition is a passing negative regression.
7. Production compilation reaches all unit repair/acceptance and workbook nodes.
8. Interface, call-site, integration-test, and shared-output ownership is closed.
9. Scheduler results are schema-bound; recovery and re-admission are
   machine-checkable; ancestor rework invalidates descendants.
10. Evidence is immutable and deterministic or uniquely run-scoped.
11. Complete deterministic, integration, adversarial, and regression suites pass
    against the final receipted code.
12. One real authorized unit reaches `UNIT_ACCEPTED` through the production CLI.
13. One real authorized full manifest reaches `COMPLETE` with exact accepted-unit
    and rendered-page coverage.
14. Final independent audit traces user requirements -> approved v2 spec -> code
    -> tests -> live receipts -> terminal.

## Honest non-activation

If an approved Claude or Codex subscription driver is unavailable, N70 or N80
may return `NOT_AVAILABLE` with content-free evidence. This permits
`REMEDIATION_VERIFIED_NOT_ACTIVATED`, never `ACTIVATED`, provider fallback, or a
recommendation to obtain an unauthorized credential.
