2. Outcome and boundaries

Outcome

A family-owned canonical record contract: one index/root, stable schemas and IDs, append-only lifecycle, digest-bound challenges and approvals, invocation receipts, non-waivable verification, and separate terminal dimensions.

Preserved variation

Questions, sources, corpora, budgets, report counts, empirical results, and conditionally applicable analysis stages may differ when explicitly declared by the plan.

Excluded authority

This plan cannot repair either historical run, approve a schema choice, accept residual risk, implement changes, or authorize release.

Prerequisites

  • A human approval must bind this exact plan version and digest before implementation.
  • The eight SOTA skills and direct dependencies must be inventoried and digest-frozen; baseline drift stops the run.

3. Planned work

  1. Freeze evidence and scope. Bind the accepted report, eight SOTA skills, direct references, family guide, schemas, validators, and both 94-file comparison packages by path and SHA-256. Preserve all 14 findings, alternatives, and six unknowns.
  2. Separate authority. Human owner controls scope, compatibility, budget, deviations, acceptance, and release. Deterministic tools own hashes, schemas, links, duplication checks, and state reduction. Models recommend but cannot grant authority.
  3. Define precedence. The method lead defines a strengthen-only rule, universal and conditional stages, compatibility policy, and the boundary between family invariants and legitimate plan variation.
  4. Map legacy runs. The incident analyst maps both existing packages to the proposed lifecycle without rewriting them, keeping facts, inferences, and unknowns distinct.
  5. Review evidence. The evidence reviewer performs bounded repository and primary-source comparison of schema versioning, provenance, append-only events, approval authenticity, and compatibility.
  6. Design the canonical contract. Specify the run index/root, stable IDs, typed extensions, schema registry, compatibility, events, digests, invocation receipts, and external-deliverable indexing.
  7. Separate status dimensions. Define independent states for research support, execution, deterministic verification, human acceptance, and implementation authority, including transitions, resume, and terminal discovery.
  8. Define mandatory verification. Add non-waivable checks for schemas, references, counts, provenance, lifecycle closure, challenges, budgets, terminal answers, and plan strengthening.
  9. Synthesize the package. Produce proposed contract, schema, validator, migration, documentation, and proving-test changes, each traced to finding IDs and preserving legitimate variation.
  10. Challenge independently. Test weakening routes, over-standardization, migration safety, ambiguous states, false passes, evidence sufficiency, and feasibility; disposition every finding.
  11. Verify independently. Check artifacts, examples, links, accessibility, compatibility, negative controls, state reachability, and challenge dispositions. Verification cannot waive failures.
  12. Return to the human owner. Present frozen artifacts, receipts, residual risks, migration choices, and exact digests. Agent completion is not acceptance.

7. Acceptance criteria

  • Legitimate research variation remains possible without weakening universal invariants.
  • A plan attempting to weaken a family rule fails before execution and identifies the stable requirement.
  • One canonical index and event record reveal execution, verification, acceptance, and authority states deterministically.
  • Missing IDs, provenance, digests, or consistent counts always fail verification.
  • External human deliverables may stay external only when canonically indexed and digest-bound.
  • Historical defects and unknowns remain visible without silent repair or blessing.
  • All Critical and High challenge findings are resolved, or the package remains unapproved.
  • Human decisions bind exact versions and digests and remain separate from implementation authority.
