5. Common method

  1. Bind the run to the approved plan and family-contract version.
  2. Record the human start decision.
  3. Run calibration only when the plan says the evidence volume or method is uncertain.
  4. Obtain protocol approval before evidence work when a separate protocol gate is required.
  5. Collect, screen, appraise, and extract evidence under the approved method.
  6. Perform incident analysis or empirical evaluation only when the plan requires it.
  7. Synthesize findings, recommendations, limitations, and unknowns.
  8. Freeze the synthesis input and run independent challenge.
  9. Disposition every challenge and correct affected artifacts.
  10. Run the non-waivable family verifier and all stricter plan checks.
  11. Produce the final-answer envelope.
  12. Request human acceptance. Acceptance and implementation authority remain separate decisions.

Plans parameterize this method. They may add steps and stricter controls but cannot skip required gates, redefine state meanings, or weaken failure behavior.

8. sota-slop-remove

Create an installed skill adapted from Lauren Tan's MIT-licensed Pstack unslop. Record the source URL, source commit, license, and adaptations.

Apply it to SOTA plans, preliminary reports, synthesis reports, verification narratives, family guides, and final responses. Remove puffery, promotional language, vague attribution, filler, generic conclusions, chatbot phrases, stacked hedges, forced triads, false ranges, abstract jargon, and decorative formatting.

Preserve every claim, evidence ID, citation, quotation, number, uncertainty, limitation, dissent, recommendation, verification result, and authority state. Exclude code, data, schemas, paths, and source quotations from stylistic rewriting. Compare the cleaned artifact with frozen source findings; any semantic change fails.

Return the cleaned artifact and a short edit count. Do not create a second narrative report about the cleanup.
