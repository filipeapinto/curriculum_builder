7. sota-slop-remove contract

The new skill will adapt the MIT-licensed Pstack unslop skill. The implementation will record the source URL, commit, license, and adapted rules.

Purpose

Make SOTA writing direct, specific, and easy to audit. It is an editing gate, not a research or decision role.

Required checks

  • Remove puffery, promotional language, vague attribution, generic conclusions, chatbot phrases, filler, stacked hedges, forced triads, false ranges, abstract jargon, and decorative formatting.
  • Delete or replace any sentence that states no fact, instruction, decision, limit, test, or supported interpretation.
  • Prefer named actors, plain verbs, exact numbers, and project-specific statements.
  • Flag text that could be pasted into an unrelated SOTA report unchanged.

Non-negotiable preservation

The skill must not change claims, evidence IDs, citations, quotations, numbers, confidence, limitations, dissent, recommendations, verification results, or authority states. Code, data, schemas, and source quotations are excluded from stylistic rewriting. Any semantic change fails the gate.

Output

Return the cleaned artifact and a short count of edits by category. Do not create a second narrative report about the cleanup.

Dependency meaning. Calibration and evidence review may run in parallel. Implementation waits for the human design gate. Challenge waits for complete cleaned artifacts. Verification waits for challenge dispositions. Acceptance waits for passing verification.

Data transfer. Repository evidence enters the method and evidence roles as read-only inputs. Their requirement mappings enter synthesis. The approved design controls implementation. The writing gate receives human-facing drafts plus frozen source findings for semantic comparison. Challenge returns findings to the responsible producer. Verification returns check results and residual risks to the human owner.

13. Acceptance tests

  1. Planning a material new skill, artifact, method, risk, control, or acceptance rule without a synchronized issue/report version fails.
  2. Removing all predecessor files leaves the current plan complete and executable.
  3. Removing all predecessor files leaves the current SOTA report complete and reviewable.
  4. No operative section relies on “unchanged,” “see previous version,” or a diff.
  5. Every mandatory family control maps to an issue criterion, verified failure, and passing/failing fixture.
  6. A study-specific output can be added by a plan without becoming a universal family artifact.
  7. Both historical runs receive truthful read-only results; unknown provenance remains unknown.
  8. sota-slop-remove removes seeded filler, vague attribution, puffery, generic conclusions, forced triads, abstract jargon, and decorative formatting.
  9. The writing gate fails when a revision changes any claim, citation, evidence ID, quotation, number, uncertainty, limitation, recommendation, verification result, or authority state.
  10. The independent challenger finds no unresolved Critical or High bypass, omission, or unnecessary requirement.
  11. All required links resolve, HTML renders without overflow, machine records validate, and deterministic tests pass.
  12. Verification PASS, human acceptance, and implementation authority remain separate states.
