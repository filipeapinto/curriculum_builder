# Plan 24 curriculum-factory acceptance criteria

These criteria govern Plan 24 implementation and release. A blocking finding
must cite a criterion, concrete trigger, operational consequence, and exact
repository or run evidence. Prose that promises future behavior is not proof.

1. **Product identity** — The implemented system's successful outcome is an
   accepted curriculum unit or complete accepted workbook. Prompt graphs,
   candidate populations, design documents, visualizations, and review records
   cannot independently satisfy the objective.
2. **Executable graph** — One immutable effective factory graph is compiled for
   the selected manifest. Its nodes, typed ports, execution edges, context
   edges, guards, joins, reducers, loops, counters, artifacts, and terminals are
   closed and validated before live work.
3. **Curriculum neutrality** — The engine derives subject, unit IDs, count,
   order, dependencies, domain schema, verifier, fixtures, calibration, and
   curriculum-owned checks from the supplied curriculum without engine
   hardcoding.
4. **Live path** — `--lab-id` and `--all` reach real policy-selected worker
   execution after preflight. A simulation, prewritten artifact, unconditional
   refusal, or manual bridge cannot be presented as the production path.
5. **Code authority** — Code alone owns graph activation, routing application,
   state transitions, joins, retries, revision routing, acceptance, resume,
   workbook coverage, and terminals. Models produce only bounded artifacts or
   structured findings.
6. **Routing and containment** — Every model call has a validated prior routing
   decision, observed executed identity, frozen request, isolated authorized
   reads, and one declared output. Bypass, mismatch, extra write, path escape,
   malformed output, or missing evidence fails before state mutation.
7. **Grounding and derivation** — Every required domain fact binds an admitted
   primary-source retrieval record; every rendered subject-matter claim and
   visual binds its declared parent and exact artifact bytes. Recall, plausible
   prose, or unresolved receipts do not pass.
8. **Unit pipeline completeness** — Research, domain validation, unit authoring,
   generic checks, visual production, receipt resolution, rendering, all-page
   inspection, independent review, verdict reduction, repair, acceptance, and
   checkpointing are executable graph nodes with complete evidence.
9. **Complete denominators** — Every compiled blocking check, required review,
   source request, artifact, and rendered page has exactly one current result.
   Missing, duplicate, stale, invalid, failed, or `NOT_RUN` evidence prevents
   acceptance.
10. **Targeted convergence** — Each repairable check has one artifact owner,
    bounded allowed diff, invalidated-descendant set, retest order, and biting
    counter. Local defects do not trigger broad regeneration; repeated failure
    cannot be relabeled success or prerequisite pause.
11. **Product QA** — Acceptance evaluates actual structured unit content,
    visual assets, unit PDF pages, and workbook pages. Prompt quality and
    successful rasterization alone cannot prove factual, pedagogical, visual,
    or release quality.
12. **Isolation and independence** — Author, reviewer, repair, and controller
    contexts are structurally separated. Reviewers cannot see sibling verdicts
    or author history; authors cannot see hidden tests or control verdicts;
    workers cannot mutate controller evidence.
13. **Durable resume** — Checkpoints bind exact inputs, graph position,
    artifacts, and hashes. Cold resume refuses changed contracts, duplicate
    continuation, out-of-order activation, invalid checkpoints, and accepted
    artifact overwrite.
14. **Manifest orchestration** — `--lab-id` processes only the legal requested
    unit. `--all` advances in manifest order without manual invocation between
    units and stops truthfully on interruption, prerequisite, exhaustion, or
    system failure.
15. **Workbook release** — Workbook assembly requires every manifest unit
    accepted exactly once in order. Every workbook page is rendered and
    reviewed; workbook-only defects cannot mutate accepted unit content; only
    successful final release audit writes `COMPLETE`.
16. **End-to-end proof** — From clean output roots, one live unit and one
    bounded unrelated full-manifest fixture are produced with no hand-authored
    intermediate curriculum files. An Arduino run demonstrates the same
    manifest-derived machinery or pauses only at a proven external prerequisite.
17. **Independent recomputation** — A separate audit recomputes graph identity,
    routing coverage, evidence hashes, check denominators, transitions, unit
    acceptance, workbook coverage, and terminal status from raw records without
    trusting controller conclusions.
18. **Truthful claims** — Documentation, deferred obligations, and final reports
    claim no more curricula, units, routes, checks, pages, resume cases, or
    releases than exact evidence proves.
